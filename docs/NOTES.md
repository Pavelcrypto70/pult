## 2. Что обсудили и решили

### Продукт
- Пульт = операционка **магазина дверей**, не multi-tenant CRM.
- Три направления канбана: Продажа · Поставка/доставка/монтаж · Постгарантийный сервис.
- Карточка сделки = центр правды; клиент живёт внутри карточки.
- Задачи шефа отдельно, с опциональной связкой `linkedDealCardId`.

### Канбан (уже в коде / в LOGIC)
- Drag карточек + история; drag блоков (порядок).
- Автопереход по **действиям** + проверка обязательных полей.
- Ручной drag → флаг `needs_fill`, не жёсткий откат (`strictFlow` опционально).
- Конструктор: блоки, шаблон полей, правила переходов.
- Handoff Продажа → Поставка: **одна сущность**, смена direction/block.

### Max «как в Битриксе»
- Не канал бота, а **личный диалог**, привязанный к сделке (`Dialog`).
- Слои: канбан → правило → Dialog → бэкенд/коннектор → Max.
- Триггер предпочтительно `action_success`, не любой drag.
- Без `linked` диалога — не шлём, пишем failed в историю.
- Токен только на сервере; Pages/localStorage — только mock.

### Кнопка «открыть чат»
- Есть `maxChatUrl` → открыть.
- Только телефон → копировать номер + подсказка «найти в Max» (нет `wa.me`-аналога).
- Писать с **личного** акка менеджера в **тред бота** — нельзя официально.
- Ответ из Пульта — **от бота/коннектора** в тот же диалог.

### Входящие в бота
- Клиент тыкнул «обратная связь» → webhook → карточка + Dialog linked.
- Личка обычного профиля человека без коннектора официально не парсится.

### Два пути Max
1. **Готовый коннектор** (Umnico / Wazzup): ~2–4 тыс. ₽/мес, быстрее «написать первым».
2. **Свой бот + бэкенд**: без подписки коннектору, больше разработки; клиент обычно сначала пишет боту.

### Бот — максималка модулей (к выбору)
Обратная связь, статус заказа, замер, каталог-интерес, оплата/доки, монтаж, рекламации, автостатусы с доски, staff-алерты, deep-link `start=ORDER_…`.

### Презентация
- Рисованное pitch-демо **убираем** из продукта (не путать шефа с мокапами).
- Решения ведём этим файлом + `LOGIC.md`.

## 4. Варианты структуры потоков (что за чем)

Ниже — **4 варианта**, как выстроить «что идёт после чего». Можно смешивать.

### Вариант A — Три параллельные доски (как сейчас)

```
Продажа          Поставка/монтаж         Сервис
[воронка]   →handoff→  [исполнение]   →опц.→  [гарантия]
```

**Плюсы:** привычный UI; у каждого направления свои столбцы и шаблон.  
**Минусы:** handoff нужно жёстко дисциплинировать; легко «потерять» контекст на стыке.  
**Кому:** салону с разделением ролей (менеджер продаж / Ксения / сервис).

### Вариант B — Один сквозной поток (одна доска «Заказ»)

```
Лид → Замер → КП → Предоплата → Поставщик → В работе → Монтаж → Закрыто
                                      ↘ Рек.поставщик → Рек.внутри ↗
```

**Плюсы:** одна правда «где заказ»; проще для шефа.  
**Минусы:** длинная доска; рекламации и сервис засоряют основной ряд.  
**Кому:** маленькой команде (2–4 человека), всё делают почти все.

### Вариант C — Основной поток + боковые ветки (рекомендуемый гибрид)

```
Продажа (короткая) ──handoff──► Поставка (магистраль)
                                   │
                                   ├─ ветка «Рекламация» (бок)
                                   └─ ветка «Доработка менеджера» (бок)
Закрытый заказ ──► Сервис (отдельная доска по обращению)
```

**Правила:**
- В магистраль только «здоровый» заказ.
- Рекламация = подпоток с возвратом в «Заказ в работе» (или терминал).
- Сервис открывается **новой карточкой** или режимом, но с ссылкой на исходный заказ.

**Плюсы:** близко к эталонному скрину поставки; не смешивает продажи и гарантию.  
**Минусы:** нужна явная модель «ветка».  
**Кому:** ваш текущий салонный процесс (Ксения / Катя / поставщик).

### Вариант D — Стадии сделки + статусы исполнения (двухуровнево)

```
Уровень 1 (стадия):  Продажа | Производство | Монтаж | Сервис
Уровень 2 (внутри):  блоки/очередь как сейчас у поставки
```

**Плюсы:** шеф смотрит крупно; операторы — мелко.  
**Минусы:** сложнее UI (вкладки стадии × столбцы).  
**Кому:** рост команды, когда 8 столбцов на одном экране мало.

## 5. Эталонные переходы (для варианта C — зафиксировать с шефом)

### 5.1. Продажа
| Из | Действие | В |
|---|---|---|
| Новая заявка | Назначить замер | Замер |
| Замер | Сформировать КП | КП |
| КП | В переговоры | Переговоры |
| Переговоры | Получена предоплата | Предоплата |
| Предоплата | В производство | В производство |
| В производство | Передать в поставку | → первый блок Поставки |

**Контракт handoff (обязательно перед передачей):** дверь/SKU, срок, контакты, предоплата отмечена, (желательно) Max dialog или телефон.

### 5.2. Поставка — магистраль
| Из | Действие | В |
|---|---|---|
| Не отправленные | Взять в обработку (Ксения) | У Ксении |
| У Ксении | Отправить поставщику | У поставщика |
| У Ксении | Нужна доработка | Доработка менеджера |
| Доработка менеджера | Исправлено | У Ксении |
| У поставщика | В работу | Заказ в работе |
| Заказ в работе | (закрытие/монтаж сдан) | терминал или архив* |

\*терминал «Готово/Сдано» можно добавить явно.

### 5.3. Поставка — ветка рекламации
| Из | Действие | В |
|---|---|---|
| У поставщика | Открыть рекламацию | Рек у поставщика |
| Рек у поставщика | Передать Кате | Рек у Кати |
| Рек у Кати | Вернуть поставщику | Рек у поставщика |
| Рек у Кати | В работу по рекламации | Рек в работе |
| Заказ в работе | Открыть рекламацию | Рек в работе |
| Рек в работе | Закрыть рекламацию | Заказ в работе |

### 5.4. Сервис
| Из | Действие | В |
|---|---|---|
| Новое обращение | На диагностику | Диагностика |
| Диагностика | На согласование | Согласование |
| Согласование | В работу | В работе |
| В работе | Ждём запчасть | Ожидает запчасть |
| Ожидает запчасть | Запчасть получена | В работе |
| В работе | Закрыть | Закрыто |

## 6. Как выбрать вариант на встрече с шефом

1. Сколько людей трогает одну карточку? (1–2 → B; 3+ с ролями → A/C)  
2. Рекламации частые? (да → C с веткой)  
3. Нужен ли отдельный постгарантийный контур? (да → отдельная доска Сервис)  
4. Max: сначала только входящий бот + ответ из карточки, или сразу автостатусы с блоков?

**Рабочая рекомендация:** вариант **C** + вход по аккаунту + MVP бота (обратная связь / статус / ответ из карточки). Автостатусы Max — второй шаг.

## 8. Архив (решение)

Полная логика — [`LOGIC.md` §17](./LOGIC.md). Кратко:

- Архив = **состояние карточки**, не столбец.
- Закрытие раньше срока = исход `lost` / `cancelled` + причина с любой стадии.
- Статистика месяцев — по событиям `history.kind = archive` (снимок суммы/исхода), чтобы возврат не затирал месяц.
- UI: «В архив» в карточке/воронке → `/app/archive` (фильтры + «Вернуть») → блок на Обзоре.
